# admhelpservice-portfolio

Портфолио-версия внутренней системы обработки заявок. Проект показывает архитектуру и основные сценарии реального Django-приложения, но не содержит рабочей базы данных, персональных данных сотрудников, секретов, внутренних адресов, production-конфигурации и истории исходного закрытого репозитория.

## Что реализовано

- несколько категорий заявок: компьютеры, принтеры, транспорт, учётные записи, ВКС и хозяйственные обращения;
- единая модель заявки поверх специализированных моделей категорий;
- роли пользователей, группы технических специалистов и назначение исполнителей;
- workflow заявок, статусы, ожидание ответа и контроль SLA;
- лента обсуждения с публичными сообщениями, внутренними заметками и вложениями;
- центр уведомлений и фоновые задачи Celery;
- интеграционные слои для почты, Telegram, GLPI и внешнего GPS API;
- серверная подготовка данных для таблиц заявок;
- аудит действий, request ID и структурированное логирование;
- тесты бизнес-правил, прав доступа, SLA, уведомлений и обсуждений.

## Архитектура

| Модуль | Назначение |
| --- | --- |
| `apps/orders` | Доменные модели заявок, формы, workflow, SLA, представления и задачи |
| `apps/users` | Пользователи, технические группы и специалисты поддержки |
| `apps/order_communication` | Обсуждения, вложения, видимость сообщений и события |
| `apps/notifications` | Уведомления, выбор получателей и непрочитанные события |
| `apps/surveys` | Опросы и обратная связь |
| `apps/garage` | Обслуживание транспорта и интеграционный пример |
| `utils` | Почта, Telegram, QR-коды и инфраструктура логирования |

В коде разделены модели, формы, selectors, services, policies, Celery-задачи и HTTP-представления. Интеграции получают параметры из окружения; в portfolio-настройках внешние отправки отключены или направлены в безопасные локальные заглушки.

## Быстрый запуск

Требуется Python 3.11+.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements/dev.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

В Windows PowerShell активация окружения:

```powershell
.venv\Scripts\Activate.ps1
```

По умолчанию используется SQLite, письма выводятся в консоль, а Celery выполняет задачи синхронно. Настройки находятся в `config/settings/portfolio.py`; безопасный перечень переменных окружения приведён в `.env.example`.

## Проверки

```bash
python manage.py check
python -m pytest
```

## Что намеренно исключено

- реальные записи пользователей и заявок;
- дампы БД, медиафайлы и выгрузки;
- ключи, токены, пароли и рабочие адреса сервисов;
- LDAP/SSO- и production-настройки;
- deployment-скрипты и внутренняя эксплуатационная документация;
- папки `.codex`, агентские инструкции и история закрытого репозитория;
- объёмные сторонние frontend-зависимости, не относящиеся к авторскому коду.

Этот репозиторий предназначен для просмотра архитектуры и качества кода. Он является обезличенным снимком, а не production-дистрибутивом.
